## 0. Обязательные решения и запреты

1. **ALTO** — рабочее утверждённое название. Официальный UI-brand — ALTO; русский текст «Альто» допустим в документации, но логотип латиницей.
2. **Выбран именно четвёртый концепт** — 3 серебристых восходящих шеврона, чёрный/графит, графитовые стеклянные карточки. Не возвращаться к прежним Monrix/Sekva и разноцветным концептам.
3. **Montserrat** — основной интерфейсный шрифт во всех разделах, RU/EN. Использовать локальную зависимость, не полагаться на загрузку по CDN. Проверить лицензию шрифта и корректно приложить уведомление при распространении; не путать шрифт с текстом, сгенерированным на референсе.
4. В версии **4.0 приоритет — дизайн + логика навигации, usability, тестируемость**, затем расширение уже существующих инструментов. Не изображать несуществующие функции работающими.
5. **Никакого пуша, PR merge и Release без отдельного согласия пользователя.** Начать работу только после его явного «начинай» в другом чате. Реализация в отдельной ветке, не на `main`.
6. Поддержка актуальных Premiere и современных UXP API важнее поддержки старых версий, но рабочую CEP-версию не ломать без готовой замены.
7. Избежать потери пользовательских материалов, настроек, пресетов, watch-папок и истории обновлений. **Не менять сейчас** CEP bundle ID `com.victor.motionviewer` и существующие идентификаторы папок / JSON без точной безопасной миграции. Имя в UI/manifest можно сменить независимо от ID.
8. Не обещать стеклянное размытие пикселей **других окон Premiere**: CSS действует внутри панели, не над чужими частями UI. Не подделывать нативные кнопки управления окном: Adobe управляет рамкой и доком.
9. Название ALTO уже существует у иных продуктов; для личного использования это приемлемый выбор пользователя, но не заявлять зарегистрированную уникальность/товарный знак.

## 2. Брендинг и логотип (P0 — обязательный объём 4.0)

**Знак:** векторная геометрическая пиктограмма из трёх восходящих клиновидных линий/шевронов, образующих A и намёк на слои таймлайна/восхождение. Чёткий силуэт в 16, 20, 24, 32, 48, 64, 128, 256, 512 px. Согласовать геометрию, толщину и оптические отступы, не генерировать иконку исключительно как растр со световыми шумами.

**Варианты одного утверждённого знака:** (а) Flat Mono: плоская серебристая фигура для маленьких размеров; (б) Soft Chrome: нейтральный металл/узкий контур, для about/splash; (в) App Icon: монохромный знак на скруглённом графитовом квадрате с аккуратным световым контуром. Проверить узнаваемость на 16/24/32 px, на светлом и тёмном фоне, grayscale.

**Wordmark:** `ALTO`, Montserrat SemiBold/Bold, без чрезмерного межбуквенного расстояния, без псевдо-3D пластиковых букв в реальной панели. Допустимо специальное рисованное «A», остальные буквы Montserrat. Буквенная надпись отдельно от знака.

**Файлы, которые подготовить после утверждения реализации:** `assets/brand/alto-symbol.svg`, `alto-wordmark.svg` (если требуется оптическая коррекция), `alto-lockup.svg`, `alto-icon-mono.svg`, favicon/PNG sizes; инструкция по использованию и лицензия. Декоративные глянцевые изображения применять только там, где они полезны, не грузить 4K-картинку в узкий sidebar.

**Ребрендинг текста:** заголовок панели, `title`, welcome/empty states, настройки, About, русский/английский язык, диагностика, справка, README/INSTALL/CHANGELOG (после согласования). Пока не изменять `owner/repo` в настройках обновления, GitHub URL, CEP bundle ID. Соблюдать ALTO caps в интерфейсе, «Альто» в тексте.

## 3. Graphite Glass 2.0 — полный UI kit (P0)

**Цвета как СТАРТОВЫЕ дизайн-токены, отрегулировать визуальным тестом:**
- background `#0B0B0D` — глубокий нейтральный графит;
- elevated `#15161A` — фон панелей;
- surface `rgba(45,47,54,.68)` — стеклянная поверхность;
- surface hover `rgba(65,67,75,.78)`;
- border soft `rgba(224,227,234,.13)`, border focus `rgba(242,244,247,.45)`;
- foreground `#F1F2F4`, secondary `#B3B5BC`, muted `#848790`;
- highlight `#E3E5E9` серебристый, НЕ постоянная яркая голубая подсветка;
- warning/error/success — семантические сдержанные цвета, только по ситуации.

**Технический слой:** `tokens.css` (цвета, радиусы, размеры, типографика, motion), `glass.css` (поверхности/fallback), `components.css` (универсальные UI), `layout.css` (responsive). Сохранить и поэтапно перенести селекторы из `styles.css`, не писать второй конфликтующий набор из сотен `!important`. Монолит `app.js` разбирать на небольшие модули постепенно, с сохранением публичных интерфейсов.

**Стекло:** 3 уровня — низко-контрастная основа, стеклянные карточки, всплывающие диалоги/ховеры. Subtle multi-stop gradients, тонкие световые фаски, внутренний свет, одна-две тени. `backdrop-filter` только где корректно работает; graceful fallback для CEP старой графики. Не применять blur к 100 постоянно изменяющимся карточкам — GPU cost. Эффекты адаптируются к `prefers-reduced-motion` и `prefers-reduced-transparency`.

**Типографика Montserrat:** 400 body, 500 controls, 600 titles, 700 важные значения. Масштаб с реальным тестом в панели: 11–13 px secondary, 12–13 px основное, 15–18 px заголовки, 20–24 px только редкие большие хедеры. Использовать табличные цифры для таймкодов; содержимое русское/английское с контролем переноса. Компоненты должны сохранять плотность Premiere, не превращаться в мобильные полноэкранные экраны.

**Геометрия:** радиусы 10/14/18/24; 4px базовая система отступов; compact mode для узкой панели; tactile press с scale <1; анимации не длиннее ~100–220 ms и с отключаемым режимом. Не использовать backdrop & box-shadow обвес на каждом списковом элементе.

**Компоненты:** app shell, brand header, tab nav, breadcrumbs, segmented controls, universal media card, compact rows, icon buttons with tooltip, slider/value/unit row, number inputs, range/dual range, toggle, section disclosure, modal/confirmation, toast, banners, state skeleton, inline error, file chip, progress, searchable menu, badges только информативные, preset gallery, mini-preview, results table, inspector layout.

**Сохранить** клавиатурный фокус, доступность, радиусы и контраст, ясный активный/disabled/error/processing state; не перерисовывать всё на каждое изменение ползунка, если можно обновить лишь контрол/превью.

## 4. UX / навигация (P0)

Вспомогательная структура: **Главная** (недавние действия / избранное / быстрые команды), **Движение**, **Библиотека**, **Звук**, **Инструменты**, **Автоматизация** (существующие макросы), **Настройки**. Существующие категории Эффекты, Переходы, Motion Zoom доступны без дополнительного глубокого перехода; конкретную шапку и минимальную ширину подобрать визуально. Никаких вкладок с пустыми «будущими» функциями.

- Сделать компактный topbar со знаком ALTO, contextual breadcrumb, глобальным поиском и настройками. В текущей узкой панели использовать иконки с tooltip + подписи по доступной ширине.
- **Глобальный поиск** по названиям RU/EN, тегам, анимациям, эффектам, собственным материалам и существующим инструментам; с фильтрами по разделу и результатом вида «название / тип / короткое действие». Если поиск не может охватить внешние эффекты без индексирования — явно указать.
- **Избранное и недавнее** не только у карточек, но и у команд/предустановок; возможность закрепить 5–8 инструментов для быстрого доступа. Не расширять existing favorites schema без миграционного теста.
- Сохранять контекст: последняя открытая вкладка, скролл, фильтр, режим grid/list, параметры пресета. Переключения не должны неожиданно сбрасывать состояние, обрывать обработчик или создавать дублированные запросы.
- **Проверка перед применением:** выбранные клипы/дорожки, возможные конфликты, ошибки, подтверждение замены уже созданных ALTO-эффектов. После действия — понятный успех и список изменений; не допускать тихих ошибок.
- **Common preview system**: кадры и элементы с реальным медиа, skeleton во время загрузки, pause hover previews, stop when hidden, короткие подписи исходных масштабов/формата, responsive canvas. Тяжёлый предпросмотр не запускается при листании.
- **Умная адаптация размеров:** узкий 300–400 px — 1 колонка и compact cards; 420–650 px — гибридная панель; широкая панель — грид/инспектор, если реально помещается. Не полагаться на CSS Grid там, где целевое окружение не поддерживает; для CEP использовать гибкий layout.
- **Время и единицы:** единые поля frame/timecode/duration, десятичный формат, шаг стрелками, нормальные допустимые диапазоны, единицы измерения и reset-to-default, форматировать в соответствии с FPS секвенции.
- **Motion Zoom:** показать последовательность точек/длительностей, использовать понятный переключатель режимов вместо массива взаимно противоречащих чисел. Не менять сами keyframes на этапе чисто визуальной миграции.
- **Звуковая панель:** всегда доступный dock mini-player, waveform, индикация времени, лёгкое управление громкостью и остановка при переключении контекста (сохранить существующие корректные правила воспроизведения).
- **Настройки:** систематизированные группы: Appearance, Library, Preview, Language, Host/Connection, Local Tools, Updates, Diagnostics/About; кнопки reset/diagnose должны быть однозначными.
- **Полная RU/EN локализация:** UI без смешения «Монтажопа», «Motion Viewer», «ALTO», за исключением технических совместимых ID; пользовательские ошибки понятные и содержат возможное действие.

## 5. Функциональные улучшения, реалистичные в рамках 4.0 (P1; включать после тестов)

1. **Motion presets experience:** аккуратный инспектор вместо длинного потока форм, compare before/after, presets with icons, one-click reset to safe defaults, clear ease-in/ease-out setting for supported modes. Ключевую математику `engine.js` не менять без отдельного теста.
2. **Motion Zoom UI 2.0:** список остановок/точек, drag-reorder при сохранении валидного порядка, числовое масштабирование, скорость/ease/hold в отдельных секциях, responsive preview с захватом кадра. Физические пути, adaptive blur нескольких слоёв, face/object tracking — **не обещать** до проверки API и масок; вынести в исследования.
3. **Media Library UX:** превью фото, видео, звука; теги, smart filters, недавние, import progress; отображение отсутствующих файлов и relink; не дублировать файлы незаметно.
4. **Watched Folders UX:** читабельная таблица: путь, назначение, включено, последний импорт, ошибки/повторная попытка, фильтры, безопасные переключатели. Имеющийся importer сохраняет ACK/retry; сторонние механики Camera card можно перенести позднее.
5. **Batch actions UX:** запускаемые по-настоящему существующие макросы и последовательности действий с кнопкой preview; не рисовать Batch Export, если backend отсутствует.
6. **Read-only Project Health starter:** UI для будущего диагностика с реально реализованными безопасными структурными проверками (если проверены), без автоматического удаления/изменения таймлайна. Отложить сложный pixel/audio audit.
7. **Keyboard UX внутри панели:** Escape закрывает окно, Enter подтверждает где безопасно, Cmd/Ctrl+K открывает поиск если это не крадёт общие хоткеи Premiere; настройка и тесты Mac/Windows. Не перехватывать системные действия при неактивной панели.
8. **Обновлятор ALTO:** ясные stable/beta версии, changelog, проверка целостности и возврат назад. Действующий downloader и SHA256/staging/rollback оставить рабочими.

## 6. Что НЕ включать в стабильный ALTO 4.0 как «готовое» без отдельной разработки (P2)

- Нативный Drag & Drop локальных медиа прямо на timeline: требует UXP и целевую версию Premiere/API, отдельная ветка `feature/uxp-library` / прототип. В CEP нельзя обещать этот путь как реализованный.
- AI-индексатор B-roll, AI rough edit, MCP-command planner, автопереключение multicam: отдельные backend/runtime/модели, длительные тесты на пользовательских данных. Можно составить архитектуру, но не рисовать неработающие кнопки.
- Настоящая динамическая маска/blur выбранных передних слоёв в Motion Zoom, трекинг лиц и плавный blur нескольких слоёв: важная пользовательская идея из прошлых обсуждений; сделать feasibility spike, не замаскировать баг «на всякий случай».
- Полная библиотека Film Impact: коммерческие нативные переходы и API нельзя имитировать названием; лицензии и оригинальные плагины — отдельная история.
- Перенос всей CEP-панели на UXP за одну итерацию. Полная миграция может стать 4.1+ после работающего прототипа.

## 8. Порядок исполнения для другого чата

**Этап 0 — baseline:** открыть GitHub repo; проверить HEAD, версию и уже существующие проблемы; создать отдельную ветку только после согласия; собрать локально старую beta; прогнать JS/Python tests; сделать screenshots baseline на 300/420/600+ px (где возможно). **Этап 1 — brand assets:** SVG triple-chevron A, монограмма, Montserrat, app icon, легальная лицензия и контроль 16–64px; сначала показать пользователю визуальный набор на утверждение.
