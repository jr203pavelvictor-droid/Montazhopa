# Как загрузить Монтажопу в свой GitHub

Твой логин и имя репозитория не были предоставлены, поэтому в файлах нет чужого адреса и не требуется правка кода: адрес задаётся в настройках установленной панели.

## Самый простой первый выпуск — через браузер

1. Распакуй внешний комплект `Montazhopa_3.1_GitHub_Kit.zip`.
2. Открой свой **публичный** репозиторий на github.com. Этот обновлятор не использует токены и не умеет скачивать приватные релизы.
3. Открой `01_REPOSITORY`. В репозиторий загружается **содержимое этой папки**, а не сама папка и не внешний ZIP. Через **Add file → Upload files** перетащи файлы и каталоги, затем сохрани **Commit changes**. Папки `com.victor.motionviewer`, `tools`, `tests`, `third_party` должны оказаться прямо в корне репозитория.
4. Папку `.github` тоже нужно загрузить, если хочешь автоматическую сборку следующих версий. Если браузер пропустил её, первый выпуск можно сделать без неё; затем добавь `.github/workflows/release.yml` через **Add file → Create new file** и вставь содержимое приложенного файла. В Windows папка с точкой обычно видна как обычная папка; на Mac скрытые файлы переключаются Command+Shift+точка.
5. Справа открой **Releases → Draft a new release**. Если выпусков ещё нет, ссылка может называться **Create a new release**.
6. В **Choose a tag** введи **`v3.1.0-beta.1`**, выбери создание этого тега. Target — ветка, в которую загрузил исходники, обычно `main`.
7. Заголовок: **Montazhopa 3.1.0-beta.1**. Описание можно скопировать из CHANGELOG.md.
8. В область вложений перетащи **оба файла из `02_RELEASE_ASSETS`**: `Montazhopa_3.1.0-beta.1.zip` и `Montazhopa_3.1.0-beta.1.zip.sha256`. **ZIP релиза не распаковывай.** Внешний GitHub Kit сюда не подходит. Автоматические вложения GitHub `Source code (zip)` тоже не являются обновлением панели.
9. Отметь **This is a pre-release** и нажми **Publish release**. До публикации вложения должны полностью загрузиться.
10. В Монтажопе открой настройки. Репозиторий: `логин/имя`, без `/tree/main`, без URL отдельного файла. Разреши онлайн-обновления и beta-версии, нажми **Проверить**.

Публикация исходников и публикация обновления — два действия. Установленная панель читает **Releases**, а не просто файлы ветки `main`. Пока ZIP не прикреплён к опубликованному релизу, обновлять нечего.

## Следующие выпуски — автоматическая сборка

В комплекте есть `.github/workflows/release.yml`. После загрузки исходников можно открыть **Actions → Build Montazhopa release → Run workflow**. Сценарий проверит код, соберёт ZIP и создаст релиз с номером из version.json. У аккаунта/репозитория должны быть разрешены Actions и запись выпусков через GITHUB_TOKEN.

Для новой версии изменяются одновременно:

- `version.json` → `version`, например `3.1.0-beta.2`;
- `com.victor.motionviewer/app.js` → `window.MZ_VERSION`;
- `com.victor.motionviewer/CSXS/manifest.xml` → обе CEP-версии **без beta-суффикса**: `3.1.0`; для `3.1.1-beta.1` уже `3.1.1`;
- CHANGELOG.md — описание изменений.

Затем commit и **Run workflow**. Можно вместо этого отправить git-тег `v3.1.0-beta.2`: workflow тоже запустится. Если номер тега не совпадает с version.json, публикация остановится. Уже выпущенную версию лучше не заменять: повышай номер, чтобы установленные панели увидели обновление.

Локальная сборка без Actions: из корня исходников выполни `python tools/build_release.py` или `python3 tools/build_release.py`. Результат появится в `dist`. Никакой npm-сборки для CEP-панели не требуется.

## Проверка первого обновления

В 3.0.0-beta.1 используй существующие настройки GitHub или обновление из локального ZIP. При обнаружении новой версии сначала нажми загрузку/подготовку, затем установку после закрытия Premiere. Полностью закрой приложение и открой снова. Сверь номер `3.1.0-beta.1` в настройках. Если уже вручную установлена эта же версия, кнопка сообщит, что она актуальна — это ожидаемое поведение.

Проверка скачанного ZIP и собственные файлы обновлятора протестированы локально. Публикация в твоём репозитории, реальная загрузка его release-asset, запуск PowerShell/macOS-установщика и Premiere в этой среде не выполнялись.
